# Technical Documentation

## Purpose
Write documentation people can follow and keep aligned with real behavior.

## Core principles
- Never invent commands, fields, or APIs.
- Warnings before risky steps.

## Practical rules
1. State audience, prerequisites, and environment.
2. Separate concepts from procedures.
3. Include examples, expected results, and troubleshooting.
4. Keep terminology consistent.

## When to activate
- Software, API, system, and procedure docs.

## How to combine with other skills
- Use Technical Writing for general technical prose.
- Use Instruction Writing for a single procedure.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Write a setup guide.
