# Root Cause Analysis

## Purpose
Find why a failure happened instead of stopping at the symptom.

## Core principles
- Earlier is not the same as causal.
- Do not blame a person when the evidence supports a process or technical cause.

## Practical rules
1. Define the observed failure.
2. Separate symptoms from causes.
3. Build a timeline.
4. Test suspected causes against evidence.
5. Split immediate cause, contributing factors, and root cause.
6. Recommend corrective and preventive action.
7. Define how to verify the cause is gone.

## When to activate
- Failures, incidents, unexpected results, recurring issues.

## How to combine with other skills
- Use Debugging for an active software bug.
- Use Incident Analysis for a security incident.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Explain why a service keeps crashing after restarts.
