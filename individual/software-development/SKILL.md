# Software Development

## Purpose
Run a software project from requirements through release.

## Core principles
- Architecture sized to the project.
- Do not claim a feature works unless verified.

## Practical rules
1. Define expected behavior.
2. Separate essential from optional features.
3. Define component interfaces.
4. Plan tests, logging, and operations.
5. Define completion criteria.

## When to activate
- Project-level software work.

## How to combine with other skills
- Use Programming for the code.
- Use System Design for architecture.
- Use DevOps for delivery.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Plan an MVP.
- Review technical debt.
