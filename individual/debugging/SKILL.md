# Debugging

## Purpose
Find the actual cause of a bug instead of applying random fixes.

## Core principles
- Expected versus actual.
- Preserve evidence.
- Do not claim a fix without verification.

## Practical rules
1. Reproduce or define the behavior.
2. Capture errors, logs, and environment.
3. Form hypotheses.
4. Change one important variable at a time.
5. Explain why the fix works.
6. Add a regression check when appropriate.

## When to activate
- Errors, crashes, unexpected software results.

## How to combine with other skills
- Use Hypothesis Formation when the cause is still wide open.
- Use Root Cause Analysis for recurring incidents.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- A 500 error after a deploy.
