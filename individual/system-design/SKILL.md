# System Design

## Purpose
Design systems that match actual requirements.

## Core principles
- Simple architecture when simple is enough.
- Name trade-offs.

## Practical rules
1. Start from requirements and constraints.
2. Map components, data flow, and interfaces.
3. Consider failure modes, security, scale, and operations.
4. Do not design for imaginary scale.

## When to activate
- Architecture, platforms, distributed systems, complex workflows.

## How to combine with other skills
- Use Software Development to execute.
- Use Cloud Computing when the design is cloud-specific.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Design a URL shortener at small scale.
