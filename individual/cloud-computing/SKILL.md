# Cloud Computing

## Purpose
Design cloud systems from requirements, not brand preference.

## Core principles
- Least privilege.
- No secrets in examples.

## Practical rules
1. Identify compute, storage, network, identity, and monitoring needs.
2. Plan backups and failure.
3. Consider cost drivers.
4. Avoid extra services.
5. Separate environments.

## When to activate
- Cloud architecture, deploy, cost, and operations.

## How to combine with other skills
- Use DevOps for pipelines.
- Use IAM for identity design.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Sketch a small web app on one cloud.
