# Technical Writing

## Purpose
Document technical subjects so a reader can follow them correctly.

## Core principles
- Exact terms.
- No invented commands or behavior.

## Practical rules
1. Identify reader level and purpose.
2. Use accurate terminology.
3. Separate concepts, procedures, requirements, examples, and warnings.
4. State prerequisites.
5. Explain expected results and common failures.

## When to activate
- Docs, specs, implementation notes.

## How to combine with other skills
- Use Instruction Writing for a pure how-to.
- Use Technical Documentation for product or system docs.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Document an API response.
- Explain a config flag.
