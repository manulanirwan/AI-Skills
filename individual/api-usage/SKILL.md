# API Usage

## Purpose
Use or integrate APIs from official documentation.

## Core principles
- Do not invent endpoints.
- Never expose secrets.

## Practical rules
1. Identify purpose, version, endpoints, auth, and response format.
2. Handle errors, timeouts, retries, and rate limits.
3. Consider pagination and idempotency.
4. Debug request and response separately.

## When to activate
- API design, integration, or debugging.

## How to combine with other skills
- Use Web Development when the API is part of an app.
- Use Technical Documentation to write API docs.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Integrate a public REST API.
