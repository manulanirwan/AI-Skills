# Hypothesis Formation

## Purpose
Form testable explanations instead of jumping to a conclusion.

## Core principles
- A hypothesis must be specific enough to be wrong.
- Not yet disproved is not proven.

## Practical rules
1. Define the observation.
2. List knowns and unknowns.
3. Generate multiple plausible hypotheses.
4. Name supporting and contradicting evidence for each.
5. Design a practical test that distinguishes them.
6. Update or drop a hypothesis when new evidence arrives.

## When to activate
- Unexplained observations, open causes, research questions.

## How to combine with other skills
- Use Debugging to run the tests.
- Use Research to gather missing evidence.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Explain an intermittent auth failure before changing production.
