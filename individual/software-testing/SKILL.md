# Software Testing

## Purpose
Design tests that verify real behavior.

## Core principles
- A test that cannot fail is useless.
- Do not claim a test passed unless it ran.

## Practical rules
1. Translate requirements into testable conditions.
2. Cover normal, boundary, invalid, and unexpected inputs.
3. Include negative cases and failure states.
4. Investigate flaky tests.
5. Add regression tests for important fixes.

## When to activate
- Test plans, cases, and suite review.

## How to combine with other skills
- Use Debugging when a test or product fails.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Write cases for a login form.
