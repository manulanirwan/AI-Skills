# Programming

## Purpose
Write, explain, review, or change code correctly.

## Core principles
- Do not invent APIs.
- Do not claim code was tested unless it was.

## Practical rules
1. Understand required behavior.
2. Identify language, runtime, inputs, outputs, and constraints.
3. Handle errors and edge cases.
4. Follow language conventions.
5. Consider security for input, files, credentials, and network calls.
6. Preserve working behavior unless a change was requested.

## When to activate
- Any request to write or change code.

## How to combine with other skills
- Use Software Development for project-level work.
- Use Debugging for an active failure.
- Use Software Testing for test design.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Write a parser.
- Review a function.
