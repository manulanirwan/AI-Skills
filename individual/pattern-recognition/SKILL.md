# Pattern Recognition

## Purpose
Find meaningful patterns without treating coincidence as a relationship.

## Core principles
- Signal versus noise.
- A pattern is not automatically a cause.

## Practical rules
1. Look for repeated behaviors, trends, similarities, and anomalies.
2. Separate meaningful patterns from coincidence.
3. Classify change as increasing, decreasing, stable, cyclical, or irregular.
4. Flag outliers.
5. State confidence and missing evidence.
6. Distinguish short-term fluctuation from long-term trend.

## When to activate
- Trends, logs, repeated failures, user behavior, incident history.

## How to combine with other skills
- Use Forecasting to project a pattern forward.
- Use Root Cause Analysis when a repeated failure needs a cause.

## Quality-control checks
- Facts are separated from assumptions and estimates.
- Nothing important was invented.
- The output matches the user's actual objective.
- A practical next action is clear when action is needed.

## Example applications
- Spot a recurring outage signature.
- Notice a content-performance cycle.
